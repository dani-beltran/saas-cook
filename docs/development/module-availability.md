# Module availability for agent-authored features

Use this implementation inventory with the [roadmap acceptance register](../06-delivery-roadmap.md#capability-to-phase-and-acceptance-matrix). A package dependency, a brief or a future-phase design is not an implemented module. Do not turn an absent module into a passing check or replace a required boundary with a permissive stub.

| Capability | Foundation implementation and extension boundary |
| --- | --- |
| Identity, sessions, password/magic-link/passkey/MFA | `packages/auth`; preserve current assurance and lifecycle enforcement. Application tenancy owns memberships/ownership; do not route lifecycle changes through an identity plugin bypass. |
| Organizations, teams, seats, ownership | `packages/db/src/tenancy.ts`, `packages/authz`; local seat admission is implemented. Account deletion and independent restore/deletion journals are in `packages/db/src/lifecycle` and `packages/authz/src/{journal,recovery}.ts`; directory synchronization remains later work. |
| Projects | `packages/db/src/resources.ts`, current API/UI. Projects belong directly to their Organization and support same-tenant direct sharing. The Workspace feature is retired; see the [removal brief](../feature-briefs/remove-workspaces.md) for compatibility and upgrade policy. |
| Local entitlement/capacity | Project policy plus generic reservations in `packages/db/src/resources.ts`; real transactions distinguish missing, disabled, zero, limited and unlimited. `DEFAULT_PROJECT_CAPACITY` is an initialization default, not an update to existing tenant policy. Provider-independent admission is not a billing ledger. |
| Service accounts/API keys | `packages/authz/src/keys.ts`, current key/account checks and explicit per-endpoint support. Only declared Project scope vocabulary is implemented. New endpoint/resource support is opt-in, including inherited child mappings. Customer key-management UI is implemented at the organization `keys` route; metadata lists require current manage permission, and mutations retain fresh authentication. |
| API | Shared oRPC and strict Zod DTOs; RPC/REST use the same services. `packages/api/src/resource-boundary.ts` declares whether each endpoint permits service accounts. A bearer header never falls back to a cookie. |
| Transactional identity/security email | React Email, encrypted short-lived delivery records and bounded worker retries. See [email workflow](email-workflow.md). Optional bulk-job notices, authoritative preferences, in-app feeds and unsubscribe/feedback suppression use the separate Phase 6 notifications service; mandatory identity/billing delivery remains separate. |
| Audit/outbox | Domain events commit atomically and contain bounded allowlisted metadata. A durable event is not automatically a notification, activity feed, usage charge or analytics event. |
| Local worker/services | Disposable PostgreSQL application/control stores, OpenFGA, mail and queue runtime support Foundation validation. Test installation helpers create isolated databases; never bootstrap an ambient database as a fixture. |
| Billing/providers/usage ledger | Phase 5 implementation: `packages/db/src/billing` and `packages/api-contracts/src/billing.ts`; immutable plans, Stripe fixed/seat adapter, durable commands/inbox, confirmed entitlements, ledger/windowed quotas and scoped reconciliation. Disabled by default; real Foundation policy needs no Stripe credentials. [Setup and limitations](../phase5/README.md), [unaccepted release gates](../phase5/acceptance.md). Provider-based metered charging remains disabled. |
| Billing/usage UI and mandatory notices | Localized billing/usage routes and dedicated encrypted billing deliveries; current owner/billing authority and recipient rechecks. This is not the Phase 6 general notification/preferences module. |
| Personal appearance/profile picture | Identity-owned color mode and private bounded PostgreSQL avatar storage; see [personal settings](../feature-briefs/personal-settings.md). This does not implement the general file module. |
| Cross-resource search and activity | Phase 6 discovery service in `packages/db/src/platform`: explicit Project/customer name registry, current resource permission checks, opaque continuations, safe activity projection and 90-day retention. Localized search/detail UI and RPC/REST are implemented. See [scope/evidence](../phase6/acceptance.md); Phase 6/M2 is accepted under the explicitly revised asynchronous-provider gate; the synthetic provider request is handed off without a required manual follow-up or erasure claim. |
| Private text files | Phase 6 Project-inherited, bounded immutable S3 upload/scan/download and expiry cleanup. Disabled until configured; see [supported formats and limits](../phase6/files.md). Bounded imports/exports use `packages/db/src/bulk` and the same immutable storage; see [module scope](../phase6/platform-modules.md). |
| Bulk import/export and analytics | Phase 6 implementation in `packages/db/src/bulk` and `analytics`: current session/tenant authorization, bounded worker jobs, typed authoritative sources, preferences, operator reports and provider erasure barriers. Optional configuration defaults off; see [analytics](../phase6/analytics.md) and [verification](../phase6/acceptance.md). |
| Platform settings and privacy | Encrypted webhook/integration credentials, dedicated audit grants, flags, personal/org deletion, receipt-only status and localized help/public routes. See [platform modules](../phase6/platform-modules.md) and [recovery](../phase6/recovery.md). |
| Enterprise identity/custom roles/support | Optional Phase 7, deferred beyond the planned Phase 8 Commercial template release. M3 requires Phase 7 and applicable Enterprise hardening. Existing FGA model types and roles are bounded; complex graphs need an explicit design and tests. |

For a feature requiring an unavailable capability, either implement the prerequisite as authorized work with its own contracts/tests or report the feature incomplete. Disabled modules remain disabled in the product brief and runtime. Do not set a flag merely because a route/template was added. Commercial and Enterprise presets cannot be declared accepted from Foundation checks.

Environment changes belong in `packages/config/src/server.ts` / `client.ts`, `.env.example` and affected runtime composition. Preserve the public allowlist, startup validation, role separation and credential-free builds. Do not use `NEXT_PUBLIC_*` for environment-specific image settings. Logs use shared LogTape/correlation boundaries. Loading a skill confers no authority to publish, provision live systems, send external notifications or change billing.

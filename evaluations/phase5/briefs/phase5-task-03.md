# Release a member seat through canonical lifecycle transitions

Use saas-evolve-feature. Add `packages/db/src/billing/member-seats.ts`, exporting `createMemberSeatService(tenancy)`. Its `deactivate(actor, organizationId, input)` accepts exactly `{ membershipId, operationKey }` and requests the canonical tenancy transition `{ membershipId, operationKey, role: 'member', billable: true, status: 'inactive' }`. This convenience operation is for an ordinary billable member; it must retain all authorization, owner protection, source publication, lifecycle fence, idempotency, seat and audit semantics of transitionMembership. It does not provide a local capacity override or promise that an external downgrade can be reversed locally. Validate input at runtime and reject extra fields. Prove a real external-truth-shaped downgrade retains occupied members, blocks new admission, then deactivation releases once; unauthorized and cross-tenant callers reject, reactivation still respects current capacity, and authority revoked between calls is rechecked. Provider adapter fixtures establish local policy behavior only.
